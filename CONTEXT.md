# Readlace — Web Page Translation

This context defines the user-facing language for translating a web page, reading a translated native Google Sheet, or opening a local spreadsheet in read-only Reader UI while preserving original content and per-site preferences.

## Current support and eligibility (2026-10-03)

Explicit page translation bypasses `translate="no"` and `.notranslate` at every readable-text/attribute/title level. Editable values and contenteditable/editor, script/style/code/math content remain excluded. Page metadata that discourages browser translation does not block Readlace.

Google Docs is temporarily unsupported. Its editor is recognized to show the unavailable state and prevent misleading DOM/editor-chrome translation; no Docs Reader read/translation operation is allowed. The Docs-specific implementation descriptions below are reserved, inactive behavior. The existing Google OAuth scope set is retained for token/build compatibility during this temporary suspension; it does not imply Docs support.

Reader partial continuation may translate newly visible eligible cells while preserving accepted results. Unresolved/oversized cells do not block untouched cells elsewhere. Each Reader owns its selected worksheet/discovery/content independently. Timeout messages distinguish waiting from cancellation, and a still-running request retains its owner slot.

Local/Drive workbook parsing additionally limits aggregate expanded ZIP content to 20 MiB and 4,096 members before SheetJS parsing. Unsupported ZIP64/multidisk/encrypted/inconsistent archives fail explicitly. Frozen panes, RTL/gridlines, authoritative point-based row heights and shared/inline rich runs are preserved from saved OOXML where supported.

## Accounts (ADR 0020)

The open-source extension has no accounts, sign-in, plans or quota. The **Managed account**, **Session verification** and plan vocabulary below is historical: it describes the frozen hosted backend and the earlier commercial build, kept for a possible hosted-key offer.

## Internal distribution and managed accounts

**Internal Chromium identity**:
The committed public manifest key fixes the Chrome/Chromium **Load unpacked** Extension ID at `imlhpiikjakgljngkdalbfgdpkniejdb`. It fixes identity only; it does not prove publisher trust or make arbitrary unpacked bytes safe. Each internal machine manually loads known local bytes for trusted development/staging use. A dev build may set `WXT_EXTENSION_PUBLIC_KEY` to the Store item's public key so its unpacked ID matches the published ID. The **Store build** (`pnpm build:store` / `pnpm zip:store`, output `.output/store/`) omits the manifest `key`; the Chrome Web Store assigns the published ID (ADR 0016).

**Minimum client version**:
Every extension request to the backend carries `X-Readlace-Extension-Version` with the manifest version. When `MIN_EXTENSION_VERSION` is set, a lower or malformed version gets `CLIENT_UPDATE_REQUIRED` (HTTP 426, never 401/429) before authentication, and the popup shows **Update required** from that JSON terminal code. A missing header is always rejected on extension-only routes (translation stages), always allowed on web-session routes (the web app sends no extension header; a present but outdated one still gets 426), and elsewhere follows `EXTENSION_VERSION_HEADER_MISSING` (`allow` by default). Health, logout and operator account management are never gated. Empty `MIN_EXTENSION_VERSION` disables the gate.
_Avoid_: force update, kill switch

**Managed account**:
An account created explicitly by the team with `pnpm account:create` or by calling its underlying `POST /v1/admin/accounts` endpoint (`signup_source='managed'`). Managed users sign in with their assigned email/password through `/v1/auth/login`, shown in the popup as the secondary **Team account sign-in**; there is no email/password self-signup, invitation, forgot-password, or self-service reset. Public users instead use **Google sign-in** (below), which creates a Google-only account with no password; such an account fails password sign-in exactly like an unknown email. A managed account gains a `google_sub` only through the Google sign-in linking rule and keeps its password. Operators reset passwords through `PUT /v1/admin/accounts/password` with `{ email, password }`, which revokes every existing session for that account; it applies only to managed accounts (`signup_source='managed'`) — a Google-signup account answers `ACCOUNT_NOT_FOUND` and never gains a password. Account management uses the backend-only `ACCOUNT_PROVISIONING_ALLOWED_IPS` allowlist. The socket peer is authoritative unless it matches `TRUSTED_PROXY_IPS`, which defaults to loopback (`127.0.0.1,::1`). For a trusted proxy, the backend uses `CF-Connecting-IP` when present, otherwise Express' `X-Forwarded-For` chain resolution. Malformed or all-trusted client addresses are denied without fallback to the proxy. The same configuration contract applies on every deployment; no hosting environment flag changes it. Cloud API clients are identified by their server's egress IP, not the browser user's IP. An empty allowlist denies management. No provisioning token is used; the extension's opaque access and refresh tokens remain unchanged.

**Google sign-in**:
Public Readlace sign-in (ADR 0012), performed on the Readlace web app (`web/`, Next.js) in a normal browser tab, never inside the extension. The backend owns the Google OpenID flow: authorization code + PKCE with `state`/`nonce` bound to the browser by an HttpOnly SameSite=Lax cookie, `openid email` scopes only, the client secret server side, and the ID token verified against Google's JWKS. Users are found by unique `google_sub`; otherwise a Google-verified email links to an existing account only when that account has no `google_sub`, the emails match exactly, and Google is authoritative for the email — its domain is `gmail.com`/`googlemail.com`, or the ID token's `hd` (Workspace hosted domain) equals the email's domain. Any other email match (for example a personal Google account carrying a verified company address) and a different subject are refused as `account_conflict`; an operator links such an account manually (docs/account-management.md). Otherwise a new account is created with `signup_source='google'`. A **handoff code** is issued only for a sign-in the extension started: the popup's **Sign in with Google** makes the background store a random **sign-in request nonce** (10-minute lifetime, bound to the tab it opens) and open `/signin?ext=<nonce>`; the web app relays it to `GET /v1/auth/google/start?ext=…`, the backend seals it into the transaction cookie and redirects to `<WEB_APP_ORIGIN>/auth/complete#code=…&ext=…`. The code is single-use, SHA-256-hashed at rest, at most 60 seconds old. The page delivers `{code, ext}` with `chrome.runtime.sendMessage` to the extension, whose manifest `externally_connectable` (from `WXT_WEB_ORIGIN`) and background sender check accept only the Readlace origin; the background accepts it only with an unexpired nonce it issued, from that tab, consumed once (login-CSRF defence), and otherwise answers `unrequested` without touching the current session. A web-only sign-in (no `ext`) gets no handoff code and completes at `#signed_in=web`. The extension exchanges the code at `POST /v1/auth/handoff` for the same opaque access/refresh token family as a password login; the current session is replaced only after the exchange succeeds. A missing, expired, consumed or replayed code fails with `HANDOFF_INVALID` (HTTP 401); a replay also revokes the family the code issued. Session verification is unchanged: every protected action, including on-device work, verifies the session, so Free still requires sign-in. Disabled unless the backend has `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`, `GOOGLE_OAUTH_REDIRECT_URI` and `WEB_APP_ORIGIN`. The same callback also issues a **Web session** for the web app.
_Avoid_: Google Workspace access, extension OAuth, copy-paste code

**Web session**:
The Readlace web app's own sign-in (issue 12), used by the account page and nothing in the extension. The Google callback creates it next to the handoff code: a separate token family holding one opaque `web` token, SHA-256-hashed at rest, valid 7 days, and held only in an HttpOnly, SameSite=Lax cookie on the API origin (`__Host-readlace_session` over HTTPS) that page script never reads. The web app sends it with `credentials: "include"`; CORS admits only `WEB_APP_ORIGIN`. It authenticates only web routes (`/v1/me`, `/v1/me/profile`, billing checkout/portal, `/v1/auth/logout-all`), never translation stages, and an extension bearer token always takes precedence. A cookie-authenticated write needs `Origin: <WEB_APP_ORIGIN>` plus `X-Readlace-CSRF: 1`. **Sign out of all devices** (`POST /v1/auth/logout-all`) revokes every token family of the user, extension sessions and web sessions alike, and deletes unconsumed handoff codes; `POST /v1/auth/web/logout` ends only this browser's web session.
_Avoid_: web login token, extension session, account cookie

**Plan**:
What an account may use (ADR 0011): `free` (on-device web page translation only, no quota), `trial` or `pro` (backend AI translation plus the Local Spreadsheet Reader, with a character quota). Plans differ only by features and quota and never name or expose a translation engine. Pro comes from a granting subscription, or from `MANAGED_ACCOUNT_DEFAULT_PLAN` (default `pro`) for a Managed account; a subscription beats the trial, and the trial beats Free. Free still requires sign-in.
_Avoid_: tier, model, engine plan, license

**Trial**:
The reverse trial (ADR 0011): 14 days of Pro from the first Google sign-in that creates the account, capped at 1,000,000 source characters in total, no card. Exactly one `trials` row per user, created in the same transaction as the account; later sign-ins, a Google link to a Managed account, and operator-created accounts never start one. Reaching the end date or the cap drops the account to Free permanently; nothing is locked or deleted. `TRIAL_DAYS` and `TRIAL_CHAR_CAP` override the defaults.
_Avoid_: free trial, demo, trial plan reset

**Entitlement**:
The account's current Plan as a snapshot, resolved by a pure function over the `trials` row, the provider-independent `subscriptions` rows (with a `provider` column; Polar writes them) and the current time, and returned as `entitlement` by `GET /v1/me` with every session verification. It carries `plan`, `source` (`subscription`, `managed`, `trial`, `trial-expired`, `trial-cap-reached`, `none`), the trial days left, the monthly quota period anchored on the signup day of month in UTC (clamped to the month end, also for annual plans), the limits (Pro 4M notify / 5M throttle / 10M hard cap per period; trial 1M over the trial; Free none) and the relevant subscription. `active`/`trialing` grant Pro; `canceled` keeps Pro until the paid period ends when it was set to cancel at period end; `past_due` keeps Pro for `PAST_DUE_GRACE_DAYS` (default 7) after the status changed; refunded, `revoked`, `expired`, `unpaid` and `incomplete` do not. The extension validates the snapshot and never derives access from client redirects or local state.
_Avoid_: license key, access flag, plan cache

**Roadmap**:
The public list of capabilities that are not available yet (ADR 0011 positioning amendment), grouped as _Đang làm_ (in progress), _Tiếp theo_ (next) and _Dự kiến_ (planned), with no dates. Only the Roadmap may mention more languages, Google Docs, PDF, Word/PowerPoint, Team, glossary or official Edge/Firefox support; every other public surface describes only what works today.
_Avoid_: feature list, coming features, timeline

**Waitlist**:
Email sign-ups from the landing page for Roadmap items, stored in `waitlist_signups` with the ticked interests and page language. Single opt-in today (a confirmation timestamp is reserved for double opt-in), with a token-based unsubscribe. No account is needed, the email never appears in logs or Product events, and the `waitlist_joined` event carries interests only.
_Avoid_: newsletter, mailing list, leads

**Quota**:
Source characters a trial or Pro account may submit for backend translation in one Quota period (ADR 0011). The Postgres **quota ledger** (`quota_usage`, migration `0007`) keeps one counts-only row per user and window; the backend stage atomically **reserves** the stage's submitted characters before any engine call (one `INSERT … ON CONFLICT DO UPDATE … WHERE used + n <= hardCap`, so concurrent stages never pass the cap) and **settles** after it: it charges only the records the backend translated and releases unresolved ones (they continue on-device, and a later retry is charged once it succeeds), or releases everything when the stage did not complete. Cache hits never reach the backend, so reloading translated content never reserves quota. Usage moves `allowed → throttled → exhausted`: notify at 80% (the `quota_80` product event and the 80% Lifecycle email through the `QuotaThresholdNotifier` hook, once per window; the first refused stage likewise sends the hard-cap Lifecycle email), above `throttleAt` (Pro 5M) the user's stages run one at a time instead of two, and a stage that does not fit under the hard cap (Pro 10M, trial 1M) gets `QUOTA_EXHAUSTED` (HTTP 402, never 429) with `{used, limit, resetsAt}` and no engine call. The client records it by JSON code (never as auth), steps down to on-device until `resetsAt` (Reader runs keep translated cells and continue on-device, or end `partial` without on-device support), and the popup shows used/limit, the reset date and a step-down banner from `usage` in `GET /v1/me`. Per-engine cost rows (`quota_engine_costs`: requests, characters, tokens, estimated micro-cents) are internal economics, never content. The official Google fallback's monthly budget is one global Postgres counter (`google_fallback_usage`).
_Avoid_: credits, tokens (as a user-facing unit), rate limit

**Quota period**:
The window a Quota counts in: for Pro, the monthly anniversary period from the Entitlement (signup day of month in UTC, clamped to the month end, also for annual plans), keyed by its start and reset at its end; for a trial, the whole trial (`started_at` … `ends_at`), whose charged characters also feed the Entitlement's `trialCharsUsed` (cap reached → Free). A new period starts from zero; nothing carries over.
_Avoid_: billing cycle, calendar month

**Lifecycle email**:
One of three transactional emails sent to the account email over SMTP (Amazon SES SMTP): the 80% quota notice and the hard-cap notice (support contact, reset date, on-device fallback), triggered by the quota ledger's first threshold crossing in a Quota period, and the trial-ending reminder, sent by the daily job to trials ending within 3 days that are still the Plan. At most one per user, kind and window, recorded in `lifecycle_emails` (migration `0008`, metadata only); bilingual Vietnamese then English until a UI language is stored; never translated content. Disabled without `SMTP_*`.
_Avoid_: newsletter, marketing email, notification (for the email itself)

**Subscription**:
A paid Pro billing agreement held by a payment provider and mirrored as one `subscriptions` row per provider subscription (ADR 0013). Polar, the only provider at launch, writes rows solely from signature-verified webhooks at `POST /v1/billing/polar/webhook`: Standard Webhooks HMAC over the raw body with a 5-minute timestamp tolerance, each `webhook-id` recorded once in `polar_webhook_events` so replays and retries are no-ops, and Polar's `modified_at` (`provider_modified_at`) ordering late deliveries. The user is the Polar external customer ID (the internal user id, also in checkout metadata); the interval comes from the configured annual or monthly Pro product. `status_changed_at` changes only when the stored status changes, anchoring the past-due grace. End-of-period cancellation stays `active` with `cancel_at_period_end` until Polar revokes it (`revoked`). A **refund** (Polar `order.refunded`, or a `succeeded` `refund.*`, partial or full) sets the row's `refunded_at`, so the user is Free immediately, and is recorded once per refunded order in `subscription_refunds` for the one-refund-per-rolling-12-months limit; a later paid period of the same subscription grants Pro again. The **reconcile command** rebuilds every row and refund from the Polar API with the same mapping (disaster recovery, ADR 0016), and the **refund calculator** (annual: paid − months started × monthly price, floored at 0; monthly: 0) gives the amount the operator refunds in the Polar dashboard. **Checkout** (`POST /v1/billing/checkout`, annual by default) and the **customer portal** (`POST /v1/billing/portal`) return Polar-hosted URLs that the extension or web app opens; opening or returning from them never grants access. Without Polar configuration every billing route answers 404.
_Avoid_: license, purchase, payment status, Pro flag

**Product event**:
One allowlisted analytics event (`signup`, `trial_started`, `local_reader_opened`, `file_translated`, `quota_80`, `checkout_started`, `subscribed`, `refunded`) with typed enum/number/boolean properties and never free text (ADR 0017). The backend relays it to PostHog keyed by the internal user id. Clients post only `local_reader_opened` and `file_translated` to `POST /v1/events`; the backend emits the lifecycle and billing events itself. The extension never contacts PostHog.
_Avoid_: telemetry, tracking pixel, analytics payload

**Persistent extension state**:
Generated Chromium and Firefox manifests disallow Incognito until a separately designed no-persist flow exists. Normal-profile state remains in extension-origin IndexedDB database `web-page-translation`, version `1`, store `kv`; content scripts never open it directly.

**Google Workspace Reader**:
The Chromium-only extension page `/reader.html` that reads the current validated native Google Sheet or Google Docs tab and shows plain-text translations without overlaying or changing the editor. At launch the native Sheets Reader sits behind the remote flag `workspaceSheetsReader` (backend `GET /v1/features`, env `FEATURE_WORKSPACE_SHEETS_READER`, default off; unreadable = off). While it is off, a native Sheet keeps the popup, which shows "coming soon — File → Download → Microsoft Excel (.xlsx), then open it in Local Reader" with **Open local spreadsheet**; an open Reader shows the same notice. Docs keeps its unavailable state, and the Drive Office path below is disabled at launch (no Drive scope): the Sheets API refuses the Office file and Reader shows the same download guidance (ADR 0015). The same production artifact targets desktop Chrome, Comet and Edge, but support is claimed per browser only after live proof. It fills a browser-controlled, user-resizable window-scoped Side Panel, with an extension-tab fallback. Native Sheets and Drive/local workbooks share the inline **Worksheet | Translate to** row (there is no Provider control; the backend routes engines), stable **Translate | Stop** slots, presentation toggle and secondary actions. Reader owns worksheet selection independently of the bound editor gid: bootstrap validates file ownership, Refresh and recovery retain the Reader worksheet, and same-file browser worksheet changes leave Reader untouched with zero discovery/provider calls. The Reader-owned worksheet dropdown changes only Reader; idle selection only loads, while active selection continues visible translation when the selected grid is ready. Rapid source changes commit only the latest result. Only an active native Sheets `GRID` uses the Google spreadsheet grid: before first paint, bounded 32-column batches scan right-to-left and discard their active-sheet values after deriving the rightmost populated absolute column; they are never sent to a provider. The immutable A-through-last-used-column sequence preserves internal blank/hidden positions. Source/layout then loads in 100-row logical pages, requesting the next page once near the final 20 loaded rows and evicting distant pages to preserve the 10,000 resident populated-record and 256,000 resident-source-character limits. Docs keeps card records for the active tab from a fixed narrow `documents.get` response. A Drive-hosted `.xlsx`/`.xlsm` opened in Google Sheets Office mode instead enters `/reader.html?office=1&sourceTabId=<tab>`: the background re-derives the file ID, downloads the latest saved snapshot with fixed Drive metadata/media GETs, enforces 20 MiB/30 seconds, streams bounded chunks to Reader, and parses in the existing Worker. Reader owns worksheet selection; it does not mirror the active Google Office tab or promise unsaved editor state. Workbook bytes remain in extension memory and only visible textual cells reach the backend translation stage after explicit Translate. Drive conversion, macro execution/preservation, Picker, `drive.file`, OCR, write/export APIs and canvas fallback remain unsupported.
_Avoid_: Google editor overlay, translated spreadsheet copy, Google page translation

**Local Spreadsheet Reader**:
The Chromium extension page `/reader.html?local=1`, a trial/Pro feature (ADR 0011), opened through the authenticated popup action **Open local spreadsheet**, where the user explicitly picks one `.csv`, `.xlsx`, or `.xlsm` file or drops it anywhere on the page. A drop of another type, of several files or of a file over 20 MiB is refused with a message before any bytes are read, and leaves an open workbook in place. The action is hidden before sign-in, is prominent for trial and Pro, opens a normal extension tab, and closes the popup only after the tab is created. **Plan gate:** only a verified Free Entitlement gates: the popup marks the action **Pro** and points to **Upgrade to Pro** without opening a tab; the Reader page shows an upgrade screen instead of the workbook (no untranslated preview) and re-reads the plan on **Check again**, a session change, or returning to the tab; the background refuses Free `LOCAL_SPREADSHEET_TRANSLATE` with the JSON code `plan-required` before any backend stage, and again if the refreshed snapshot turns Free mid-request. A missing or unreadable snapshot opens the Reader and leaves enforcement to the backend (`ENTITLEMENT_REQUIRED`). It does not intercept or modify browser/Office viewers. Parsing runs inside a dedicated bounded Worker; source bytes remain local to that extension process and are never uploaded, persisted, logged, cached, or sent to a provider. Google OAuth and Google APIs are not involved. Translation requires the existing Managed account session and dispatches only visible untranslated textual cells through the backend-routed translation stage.

Local Spreadsheet Reader preserves worksheet order, absolute A1 positions/internal blanks, values, formulas with available cached display, merges, row/column sizes, hidden dimensions and best-effort basic styles. It does not calculate formulas or promise exact Excel rendering. Charts, images, pivots, conditional formatting and external-data refresh are excluded. `.xlsm` is read-only with `bookVBA: false`: VBA is never executed, exposed, preserved, written, downloaded or exported. Password-protected/encrypted workbooks fail explicitly; no local workbook is edited, saved or exported. Fixed limits are 20 MiB/file, 50 worksheets, 100,000 used rows, 16,384 columns, 10,000 populated records and 256,000 source UTF-16 units per selected worksheet, plus a 15-second parse timeout.
_Avoid_: Office viewer integration, uploaded workbook, editable workbook, macro support

**Reader selection**:
For Docs cards, explicit records checked inside Google Workspace Reader for **Translate selected**. In the Sheets grid, selection exposes accessible cell details with source and translation; it is not a provider-work selection. Neither mode inspects, moves, or claims the Google editor cursor or selection.
_Avoid_: Google selection, editor selection, selected cells in Google

**Reader translation**:
The Sheets-grid generation starts only after explicit **Translate**, a source-bound popup Translate intent, or an active Reader dropdown continuation, and schedules untranslated cells in the viewport plus one viewport ahead with one Reader message pending. `idle` shows **Translate**; `translating` shows its spinner and **Translating…**; `watching` shows disabled **Translation on**; `paused`, `partial`, and `error` expose **Resume translation**, **Retry unresolved**, and **Retry** respectively. **Stop** always occupies its slot and is enabled only during `translating`/`watching`. Completion counts are visually hidden announcements; only actionable partial/warning/error states remain visible. Same-file editor worksheet changes leave Reader selection and content unchanged with zero discovery/provider calls; active Reader dropdown changes continue after load. Direct Reader opening remains load-only; Stop, Clear view, Disconnect Google/logout, teardown, settings changes, or new-file navigation stops continuation. Translation replaces source text visually; **Translation / Original** changes presentation without dispatching or clearing accepted results and stays disabled until a translation exists. Grid columns, merges and frozen panes follow the source; rows start at their source height and grow (never shrink) so every source and translated text is fully visible, using the larger of the two so **Translation / Original** never shifts the grid. Text keeps its source mode while it fits (**overflow** across empty neighbours up to the first blocker, **clip**, **wrap**); text that would be cut wraps instead, overflow text across its own corridor. Text is never ellipsized; selected-cell details expose the full translation. Docs retains explicit loaded/checked-card translation. Both use the authenticated backend-routed translation stage (OpenAI with the budget-capped official Google fallback inside the backend), existing cache validation/namespaces and concurrency `2`, without a page run, client fallback loop, browser-native stage, history or provider choice. One record is limited to 4,000 UTF-16 units; one message is limited to 128 records and 8,000 aggregate units. Results are bound to the Reader owner/source version, source tab, file/sheet/Docs-tab, grid generation, target, request, source hashes and Managed account generation, so stale work cannot update Reader.
_Avoid_: page run, Reader fallback chain, live editor translation

**Backend deployment**:
The NestJS backend requires PostgreSQL plus runtime `OPENAI_API_KEY` and `GOOGLE_TRANSLATION_API_KEY`; omitting `ACCOUNT_PROVISIONING_ALLOWED_IPS` denies account management. Optional `GOOGLE_FALLBACK_MONTHLY_CHAR_BUDGET` (non-negative integer, default 500,000 source characters per UTC month, `0` disables the fallback) caps the official Google Cloud Translation fallback in one global Postgres counter shared by every backend process. Translation uses one authenticated route, `POST /v1/translation-stages`, with no provider or engine parameter. `WXT_BACKEND_URL` is required and pins the extension to one credential-free origin: HTTPS for remote backends, or loopback HTTP on `localhost`, `127.0.0.1` or `[::1]` for local verification. The reference deployment is a single AWS Lightsail host running `deploy/docker-compose.yml` (Caddy, web, API, Postgres) with hourly off-box `pg_dump` backups, operated through `deploy/RUNBOOK.md` (ADR 0016); other managed Node services, servers, and VPS hosts use the same environment contract.

**Session verification**:
Every protected translation action verifies the backend session before returning saved text or dispatching provider/native work, including automatic, frame, title, attribute and selection paths. There is no polling or auth TTL cache: an idle popup has no automatic sign-out deadline. A valid refresh continues the action. Definitive rejection after recovery produces `auth-required` and invalidates that login generation once; network, timeout, 429, 5xx or malformed auth responses produce `auth-unavailable`, block the action, and retain the refresh token for retry without signing in again. In-flight work stops when a response or the next protected operation detects denial; already accepted DOM remains, and **Show original** remains available. Old responses, queued work and cache writes cannot cross into a new login, including the same account. Saved translations and preferences survive invalidation.

## Language

**Provider settings**:
The user's translation provider configuration (ADR 0020): the active provider (OpenAI only today), its model and the user's own API key. A versioned record in extension-origin IndexedDB, read only by the background and changed only from the Settings page (`/options.html`). Every other surface sees a masked view (`sk-…abcd`), never the key.
_Avoid_: account, plan, subscription, hosted key, credentials store

**Engine source**:
Which engine a translation starts from: `byok-openai` while a provider key is saved and not rejected, otherwise `on-device`. A future hosted offer adds a source without changing the translation flow.
_Avoid_: plan, tier, provider choice per run

**UI locale**:
The language of the extension's own interface (popup, Reader pages, selection panel, Store name and description): Vietnamese or English. It is independent of the **Target language**, the **Page language** and the landing page language. Until the user chooses, a browser UI language starting with `vi` (`i18n.getUILanguage()`) gives Vietnamese and every other language English; the popup's **Language / Ngôn ngữ** switch (account menu, or the sign-in panel while signed out) stores an explicit choice under `uiLocale` in the extension IndexedDB `kv` store. Only the background reads or writes it (`UI_LOCALE_GET` from any extension context, `UI_LOCALE_SET` from extension pages only); a change is broadcast as `UI_LOCALE_CHANGED`, so the open popup and Reader pages switch at once, while the selection panel asks the background again on its next open. Messages live in typed catalogs (`lib/i18n`), English as the source of truth; JSON codes are mapped to messages at the UI edge, never the reverse. The Store name and description come from `public/_locales` (`default_locale: "en"`, plus `vi`).
_Avoid_: interface language setting, extension language, translation language, app locale

**Page language**:
Evidence about the language of the tab, resolved from the top-frame `html[lang]` plus `tabs.detectLanguage` and reused by nested frames. The popup shows the resolved label; only agreement on the same `en`, `vi`, or `ja` produces `autoSkipTarget`. Conflict, missing, invalid, or `und` evidence never produces an automatic skip. This evidence can skip **Always-translate** only and never blocks explicit **Translate**.
_Avoid_: source language, origin language, input language, detected source, Source

**Frame**:
One HTML document in the tab: the top page or a nested iframe. A translation run and Show original cover every injected frame, including frames that load later while the Always-translate preference remains enabled and skip does not apply.
_Avoid_: tab, window, nested page, embed

**Translation engine**:
The service that translates a record. In the open-source extension (ADR 0020) it is OpenAI, called directly from the background with the user's own API key and chosen model, retried at most three times per record inside one local translation stage, with no Google fallback; records it leaves unresolved go to the on-device stage. The backend's OpenAI → Google Cloud chain (ADR 0014) is kept only for a future hosted offer. Engines are never shown as a provider choice per run.

**Translation path**:
Where a translation runs, chosen by the pure client selector `chooseTranslationPath(engine source, native availability)` (ADR 0020): `provider` (a saved, accepted provider key: the local provider stage, then the on-device recovery stage), `native` (no key, or OpenAI rejected the key: saved translations, then on-device per record) or `unavailable` (neither). The **Engine source** comes from the provider settings, not from a plan.
_Avoid_: translation provider, provider selection, Google-selected run, OpenAI-selected run, provider source, site provider, cache provider

**Provider source**:
The language route resolved independently for each eligible record. Japanese-script records use `ja`; otherwise a compatible trusted Page language hint is used, and ambiguous records use `auto`. The same route owns provider input, local validation, native recovery, and Saved translations identity; it is not the page-language label or one page-wide source.
_Avoid_: source language, locked source, detected source, page-wide source

**Target language**:
The single language selected for the current translation run: English, Vietnamese, or Japanese.
_Avoid_: output languages, multiple targets

**Selected text**:
A single nonempty range of readable page text captured in one Frame after the user completes a mouse or keyboard selection. It may cross inline nodes and rendered lines, but it excludes input, textarea, contenteditable/editor content, ranges that touch them, and cross-document or shadow-root selections.
_Avoid_: selected field value, editor selection, page source

**Selection translation**:
A user-triggered translation of Selected text shown as plain text in a floating Readlace panel. The lightweight manifest bootstrap and runtime controller share one eligibility reader, so blank, multi-range, editable and cross-root selections cannot trigger the heavy runtime or later become translatable through divergent checks. After the first eligible selection, the background injects only the fixed isolated-world React runtime into the sender `documentId`, falling back to the validated sender frame only where document targeting is unavailable. The runtime remains loaded for that document's lifetime after first use. The closed-shadow panel uses the shared compact Select component, portals its lists within the same ShadowRoot, and uses direct Lucide action/loading/error icons while the trigger keeps the Readlace brand icon. Its fixed pixel typography, controls and icons do not inherit a page's root font scale. A long result scrolls inside its labelled surface without chaining boundary wheel input to the page. The result surface expands/collapses over 180 ms, re-clamps inside the viewport, and disables motion for reduced-motion preference. Closing or repositioning the panel preserves a reopen icon and result while the Selected text remains eligible. Its target starts as English per document and may be English, Vietnamese, or Japanese. The panel has no provider control. Changing its target does not write the global Target language or Always-translate preference and cannot change a current or future Translation run. **Translate** snapshots the panel target into an explicit request to the authenticated backend-routed stage; a request carrying a provider is rejected, and later UI/global changes cannot retarget the pending request. Selection work does not join or cancel a Translation run. Firefox selection runtime requires Firefox 102 or later.
_Avoid_: partial page translation, selection run, inline replacement

**Translation run**:
A user-triggered or preference-triggered attempt to translate discovered eligible records in every frame in the tab from preserved original content. A new target restores the page before starting; same-target **Translate** from `partial` starts a new generation for the discovered active unresolved records only and keeps accepted DOM, Saved translations, and exact-restore ownership unchanged. Each eligible connected record follows exactly: valid OpenAI v10 or chain v1 cache → one authenticated backend translation stage → one browser-native attempt for a known supported non-target `ja|en|vi` route → unresolved. Inside the stage the backend makes at most three OpenAI attempts (500 ms and 1,500 ms delays or bounded `Retry-After` up to 30 seconds, retrying only failed or quality-missed records) and then at most one official Google Cloud Translation call for the still-unresolved records while the monthly Google budget remains; Google failure is never retried. The client re-dispatches a stage only after a transport-level failure where the backend did not complete it (HTTP 408/429/5xx or network), with the same delays and at most three dispatches; records a completed stage left unresolved go straight to native. `auto` and same-target routes skip native; unavailable, stalled, rejected, stale, or detached outcomes remain unresolved. Stages are sequential, accepted records never enter a later stage, and on the trial/Pro `backend` **Translation path** the per-record ceiling per generation is `3 OpenAI + 1 Google` inside a completed backend stage plus `1 browser-native`; on the Free `native` path it is cache → `1 browser-native` → unresolved, with no backend stage. Popup busy semantics cover the entire chain until terminal state. Explicit **Translate** always overrides Page language evidence. It is disabled while signed out, while translating/preparing, or when the selected target is already completely applied.
_Avoid_: translation session, batch job

**First visible translation**:
The first moment in a Translation run when an accepted translation is visibly retained on the page. It is not the provider's first token or first completed network response.
_Avoid_: time to first token, first response, loading feedback

**Viewport completion**:
The moment when a Translation run has settled every discovered eligible record in the current viewport and no provider work for that viewport remains. A fast Partial or error is not translation success and is evaluated separately from completion speed.
_Avoid_: full-page completion, whole-document completion, provider response time

**Always-translate preference**:
A setting stored for the registrable domain (eTLD+1), not the exact hostname, that remembers the target language without starting a translation run when checked. Sibling hosts under the same eTLD+1 share it (`www.yahoo.co.jp` and `news.yahoo.co.jp` share `yahoo.co.jp`; `www.example.com` and `example.com` share `example.com`). The first run requires Translate; later reload or document load auto-starts unless `autoSkipTarget` equals the preference target (Unknown still auto-translates). This automatic cost policy does not apply to explicit **Translate**.
_Avoid_: global auto-translate, cache setting

**Saved translations**:
Accepted results stored independently per normalized record and scoped by model or recovery chain, Provider source route, and Target language. Runs prefer a valid OpenAI v10 hit, then a valid chain v1 hit, before backend dispatch. A backend result with provenance `openai` is written only to the OpenAI v10 namespace; one with provenance `google` only to the chain namespace with `p: "google"`. Chain keys are exactly `translationCache:chain:v1:openai-google-native:<route>:<target>:<sha1(normalized-source)>`; values contain accepted text plus provenance `google` or `browser-native`. Every hit is locally revalidated, and a chain entry is written only after its result remains accepted in connected current DOM. Chain entries never write into or impersonate the OpenAI namespace. The legacy client-selected Google namespace (`translationCache:google:`) is no longer read or written. Bulk reads and writes let cache hits and duplicate owners reuse accepted results without provider calls, regardless of DOM piece boundaries, page URL, record order, sibling failures, or run generation. Failures are never saved, and storage failure does not undo accepted DOM. Saved translations are independent from target-language and always-translate preferences.
_Avoid_: translation cache, browser cache, page preference

**Clear saved translations**:
The action that removes the OpenAI, OpenAI-chain and legacy Google saved-translation namespaces plus local aggregate translation diagnostics without changing settings/preferences or restoring the page.
_Avoid_: clear cache, delete cache

**Show original**:
The action that restores every frame in the tab to its preserved original content without starting a new translation run.
_Avoid_: toggle translation off, stop translation

**Partial**:
A terminal translation-run result in which accepted and discovered eligible unresolved records coexist after the run's bounded backend/native chain has finished. It never schedules those unresolved records by itself; same-target **Translate** starts one explicit unresolved-only generation.
_Avoid_: translated, retrying, resumed run

**Translated**:
The disabled Translate-button state when every currently discovered eligible record is complete for the selected applied target. It is discovery-relative under lazy viewport-plus-one-viewport eligibility: offscreen undiscovered content does not make the state Partial, and newly eligible work may temporarily change the popup to **Translating…**. Scroll-back never resends accepted records.
_Avoid_: whole-document scan complete, every offscreen record translated
