# Engineering lessons

Read this file before every code change.

## Bring-your-own-key override (2026-10-31, ADR 0020)

This section overrides older clauses below that describe the backend stage, plans, quota and backend-owned keys.

- Engine calls no longer go through `POST /v1/translation-stages`. The background runs the same router (`shared/engine-router.ts`, moved from the backend) locally with the user's OpenAI key (`lib/byok-stage.ts`) and no Google fallback, so OpenAI attempts may use the whole stage deadline. The per-record ceiling per generation is `3 OpenAI` inside one local stage plus `1 browser-native`. Retryable outcomes (empty, source-identical, network, 408, 429, 5xx) stay inside the stage; a completed stage leaves the rest unresolved for native, and the client never re-dispatches it.
- A non-retryable OpenAI error other than 401/403 (a bad request, an unknown model) throws from the stage as a run failure, so the run drains and settles `partial` or `error` exactly as a failed backend stage did (CR-001). A 401/403 instead marks the key rejected: from then on `credentials()` returns nothing, so batches already running make no further OpenAI call and their records go to native; `getApiKey` keys off a saved key, not an accepted one, so a mid-run rejection never turns into a missing-key run failure.
- The key lives only in extension-origin IndexedDB (`providerSettings`). `lib/provider-settings-host.ts` in the background is its only reader; only `/options.html` may read or change settings, and every other sender gets `forbidden`. It never enters content-script or Reader messages, the translation pipeline (`getApiKey` returns a marker), logs, diagnostics, errors or popup payloads (masked view only). Older clauses saying no provider key is accepted from or stored in the extension are superseded.
- The path selector depends on the **Engine source** (`byok-openai | on-device`), not on a plan; the path literal is `provider` (formerly `backend`). OpenAI 401/403 marks the key rejected, which is not an auth failure: later work goes native until a new key is saved or a key test passes, and the session, refresh token and logout broadcast are untouched.
- `tests/background-runs.test.ts` proves key confinement end to end: after real page, selection, cache, status and diagnostics traffic, the key appears in no response, broadcast, console output or saved value, and only in the `Authorization` header of requests to `api.openai.com`. Keep that test passing for every new message or surface.
- **Copy diagnostics** (`DIAGNOSTICS_GET`, Settings page only) builds its report in `lib/diagnostics-report.ts` from an explicit allowlist: versions, UI locale, engine (provider, model, key configured/rejected), on-device support, build flags and run counts. Add a field there deliberately; never spread an object into the report.
- The uninstall survey (`WXT_UNINSTALL_SURVEY_URL`) accepts only a plain HTTPS URL with no query, fragment or credentials, so it cannot carry an identifier; unset means no page.
- Saved OpenAI translations are scoped by the chosen model (`translationCache:openai:v10:record:<model>:…`); the recovery chain cache is not.
- Plan gates (Local Reader `plan-required`, quota step-down, `ENTITLEMENT_REQUIRED`) are gone from the extension. The backend keeps them for a possible hosted offer.
- There are no accounts. The background has one local identity (`LOCAL_USER`, id `local`) and a constant generation; `authorize()` only waits for the provider settings. Run, Reader, cache and Google-token ownership checks keep their shape and bind to that identity, so a Google Workspace token record carries `managedAccountId: "local"`. Sign-in, sign-out, the web handoff (`externally_connectable`), billing, product events and `/v1/features` are removed; `AUTH_STATUS` keeps its name and returns `{ authenticated: true, user, onDeviceTranslation, engineSource, providerKeyRejected }`.
- The toolbar always routes supported editors to the Reader (no signed-out state). The native Sheets Reader is the build flag `WXT_SHEETS_READER=true`, read on every request; deterministic e2e builds set it. `pnpm build` no longer needs `WXT_BACKEND_URL`.
- The sections below on session failure, handoff binding, the quota ledger, lifecycle email and the Local Reader plan gate describe the frozen backend and the earlier commercial build. They do not apply to the extension.

## Current eligibility and support override (2026-10-03)

- User-authorized translation bypasses `translate="no"` and `.notranslate` on all readable page text, attributes and title. Preserve editable values and contenteditable/editor/script/style/code/math exclusions, including when mutation collection starts inside a protected ancestor.
- Google Docs is temporarily unsupported: recognize its route for the unavailable state and suppress DOM/editor-chrome translation, but reject Docs Reader work. Older Docs-specific clauses below remain inactive while this override applies.
- A translated title is owned only while its element and bytes match the source/accepted snapshot. Commit/restore must not overwrite a newer title from the host SPA.
- Reader partial state permits fresh visible work. Keep accepted results and block overlapping owner retries until an old physical request settles; a timeout alone is not proof of cancellation.
- A visible source can become hidden while awaiting a provider. Do not capture collapsed layout: retain successful slots in run-owned pending results, validate run/account/source again on reveal, then apply/cache with no resend or fallback. Exclude extension-owned wrappers/markers from text and attributes.
- A content-hugging ancestor is not dedicated capacity. Include descendant chrome in the existing used-geometry reasoning; integer clientWidth rounding must not cumulatively shift peers or let shorter text shrink a stretched block in an intrinsic owner. Preserve the1px proof threshold.

## Session failure ends the action before recovery stages

- Verify the session on every protected operation before provider, saved-translation or native work, including BEGIN, automatic runs, batches, title, attributes and selection. There is no polling or auth TTL cache; an idle popup has no logout deadline.
- A successful refresh continues normally. Definitive unauthorized after recovery is `auth-required`; network, timeout, 429, 5xx and malformed auth data are `auth-unavailable`. Both stop the action before retry/fallback/native. Unavailable keeps the refresh token and never broadcasts logout. `CLIENT_UPDATE_REQUIRED` (HTTP 426, ADR 0016) stops the same way and keeps the refresh token; the popup shows **Update required** from that JSON code, never from message text.
- Invalidation retires a login generation once. Pending waiters settle, while late responses, retries, dedup results and cache writes cannot affect a later login, even for the same user. Detection occurs at the next protected action or in-flight response, not at an instantaneous remote-reset deadline.
- Keep accepted DOM and exact restore ownership. **Show original** must work after revocation; saved translations and preferences are not cleared. Runtime messages carry JSON terminal codes, never message-text classification, and stale popup completion cannot overwrite a newer auth state.

## Translation success must survive layout handling

The 2026-08-20 regressions had three interacting root causes: layout fallback restored source text after provider success, the piece was still marked complete, and global constraint revalidation let one stale record reject unrelated translations.

Keep these rules together:

- A successful provider result for an eligible connected Text record stays translated. Exact source is for explicit restore or cancellation before application, never a layout fallback.
- Classify before mutation: mixed-inline flow stays raw and readable; bounded and sole-text single-line content uses full raw text when it fits or item-owned ellipsis when it does not; bounded and sole-text multi-line content preserves its captured visible footprint with a clamp. Unsupported wrapper cases retain raw translation.
- Capacity belongs to the item, not a shared row or sibling. Validate and repair only the current ownership group, with at most one source-width constrained retry; one record cannot poison another.
- Mark a piece complete only after every successful nonempty result remains installed. Failed, empty, detached, or stale work stays incomplete.
- Reuse the existing lazy scheduler: prefetch one viewport, keep one in-flight request per record and run, and preserve discovery-relative terminal semantics without an eager whole-document scan. Engine calls go through one authenticated backend route, `POST /v1/translation-stages`, which takes no provider or engine parameter and rejects one (ADR 0014); backend-owned `OPENAI_API_KEY` / `GOOGLE_TRANSLATION_API_KEY` are both required at bootstrap, and no provider key is accepted from, stored in, returned to, or built with the extension. Each eligible connected record follows exactly valid OpenAI v10/chain v1 cache → one backend stage → one browser-native attempt → unresolved. Inside the stage the backend makes at most three OpenAI attempts, retrying only empty, source-identical, network/timeout, 408, 429, and 5xx outcomes after 500 ms and 1,500 ms or bounded `Retry-After` up to 30 seconds within a 60-second stage deadline that reserves 10 seconds for Google, then at most one official Cloud Translation call (`translation.googleapis.com/language/translate/v2`, `format=html`) for the still-unresolved records while `GOOGLE_FALLBACK_MONTHLY_CHAR_BUDGET` remains. Google failure is never retried; a spent budget skips Google and returns the records unresolved with HTTP 200, never 429. Accepted, permanent/configuration, oversized, stale/detached, and cache/storage outcomes are never replayed. The client re-dispatches a stage only after a transport-level failure where the backend did not complete it (408/429/5xx/network), with the same delays and at most three dispatches; records a completed stage left unresolved go straight to native. Stages are sequential; accepted records never enter a later stage or consume later-stage budget. On the trial/Pro `backend` path the per-record ceiling per generation is `3 OpenAI + 1 Google` inside a completed backend stage plus `1 browser-native`; on the Free `native` path it is cache → `1 browser-native` → unresolved with no backend stage. There is no client provider choice, Google-selected run, or `translate-pa.googleapis.com` endpoint.
- Cache accepted translations per normalized record, scoped by model or recovery chain, per-record source route, and target. A valid OpenAI v10 hit wins over chain v1; a valid chain hit wins over backend dispatch. A backend result with provenance `openai` goes only to OpenAI v10; provenance `google` goes only to the chain with `p: "google"`. Chain keys are exactly `translationCache:chain:v1:openai-google-native:<route>:<target>:<sha1(normalized-source)>`, values contain accepted text plus exact provenance `google | browser-native`, hits are locally revalidated, and writes occur only after retained DOM acceptance. Chain entries never impersonate the OpenAI cache. Bulk-read unique keys, fan hits and accepted duplicates to every owner without provider budget, and bulk-write each accepted record even when a sibling fails. Never persist failures; storage failure is diagnostic-only and cannot roll back accepted DOM. **Clear saved translations** removes the OpenAI, chain and legacy client-Google (`translationCache:google:`) namespaces and diagnostics, not settings/preferences.
- Resolve provider source per record: Japanese script wins as `ja`, otherwise use a compatible trusted page hint, otherwise `auto`. The same route must drive cache identity, provider input, validation, and native recovery; do not hard-source a mixed page from one page-level label. Native runs at most once, watchdog-bounded to 30 seconds, only for a resolved `ja|en|vi` route different from target; `auto`, same-target, unavailable, stalled, rejected, stale, or detached work remains unresolved.
- A same-target `partial` click keeps the **Translate** label and starts a new bounded generation over one snapshot of discovered active unresolved records without restore; each such record receives a fresh backend-stage and native budget. Accepted DOM and exact-restore ownership remain intact. **Translated** is discovery-relative under viewport-plus-one-viewport eligibility, newly eligible records continue automatically, delayed retries do not block unrelated work, and scroll-back never resends accepted records.
- The background path selector (`lib/translation-path.ts`, ADR 0011/0014) decides `backend | native | unavailable` after every session verification, for page text, frames, attributes, titles and selection. Free is native-primary: it reuses the existing per-record browser-native stage, its watchdog and the chain cache (`p: "browser-native"`), and valid Saved translations still apply; misses never reach the backend, which refuses Free with `ENTITLEMENT_REQUIRED` (HTTP 403, never 429) before any engine call. A backend refusal from a stale snapshot is classified by JSON code, leaves that stage's records unresolved for native, refreshes the snapshot and switches later work to native; it is never `auth-unavailable`. Quota exhaustion is the same kind of refusal: `QUOTA_EXHAUSTED` is HTTP 402 with `{used, limit, resetsAt}` in the JSON error body, never 429 (429 is `auth-unavailable`), and the client holds the native path until `resetsAt`. Session verification still precedes native work. Native throughput comes from reusing one prepared session per pair with up to 4 pipelined `translate()` calls, never from touching `layout-ellipsis` or `content.css`.
- Browser-native preparation starts from the same trusted **Translate** click for every run, survives popup closure, and uses feature detection only. Chrome documents Translator support for desktop extensions from Chrome 138+, while general documentation also says it is unavailable in Web Workers; installed-runtime capability evidence therefore governs every native-success claim. Unavailable or stalled preparation settles truthfully after the watchdog; it never exposes setup/retry controls or mutates editable values.
- Preserve Text identity and exact restore cleanup. Add no site rule, host mutation, observer, listener, timer, provider endpoint, dependency, or eager whole-document scan.
- Layout or translation-lifecycle completion requires deterministic per-stage order/count/cache/provenance proof, package proof, a browser-native capability attempt, authenticated backend OpenAI → official Google fallback evidence, existing performance gates, and recorded headed Asahi, Wikipedia, and Yahoo attempts defined by ADR 0004. Deterministic evidence cannot substitute for external provider/native success; live unavailability is a recorded proof boundary, not a pass or product failure.
- Performance claims require same-machine cold/warm deterministic evidence: warm accepted records and scroll-back make zero provider calls, automatic retries and partial generations request exactly unresolved cache misses, no generation exceeds the per-record ceiling above, the backend-stage adapter stays at concurrency `2`, and live provider timing remains observational rather than deterministic proof.
- Provider, cache, lifecycle, collector, and coverage work must not modify `lib/translate/layout-ellipsis.ts`, `lib/translate/layout-ellipsis.test.ts`, or `assets/content.css`, or weaken raw/ellipsis/clamp/title/geometry/restore proof outcomes. Layout changes require a separate ADR revision and explicit user approval; successful connected translations never source-roll back through layout except explicit restore or stale-run cancellation.

The governing policy is `docs/decisions/0004-layout-ellipsis.md`.

## Google editor content belongs in a bounded Reader

- Reader loading class names must survive the configured Tailwind formatter. Keep full class strings in conditional branches instead of a leading-space fragment that formatting can trim into `spreadsheet-source-stateis-loading`. Assert class-token membership after formatting and measure loading source bounds against the remaining results viewport for native and Office paths; skeleton visibility or a minimum height alone does not prove layout. Keep the Reader brand visible during Root identification.

- Exercise the real global toolbar first-open and Refresh for both XLSX and XLSM. A source-bound extension tab cannot prove a bare `/reader.html` Port works. The original sender URL authenticates the surface, while a validated Context document/owner/window/source binding authorizes data access. Actual `getContexts()` can return `windowId=-1` and Side Panel MessageSender can omit `documentId`; test browser-confirmed unique document/open correlation, ambiguous multiple-document fallback, retirement and two-window isolation rather than trusting positive-window/document mocks.
- Keep settings, catalog and content readiness separate. Native pre-start metadata identifies worksheet titles without values; dropdown/Refresh remain metadata-only. Never display raw gid as a title. Office worksheet names need parsing, so show a placeholder and make zero media requests on a new-file awaiting-start. Do not label a local transport closure as a proven Google Drive outage.
- Preserve positive saved column widths down to one pixel instead of widening narrow separator columns to a generic UI minimum. Measure the workbook Normal font's maximum digit width once in the Worker, use bounded OOXML relationships/styles for fill/font emphasis/alignment/border colors and blank styled cells, and keep unsupported exact font sizing, border patterns and conditional formats explicit.
- Match content-visibility's intrinsic row estimate to the default 21px row. The grid measures rows before skipped content is painted; an intrinsic 28px estimate can enter the monotonic height cache and permanently inflate otherwise short rows. Compact cell padding must preserve actual higher source/content heights.
- Absolute merged grid cells already use their explicit grid area as the containing block: use zero inline inset, with only scroll compensation for frozen columns, never add row-header/column offsets again. Derive every merge height from final row offsets including growth reserved by other overlapping row spans. Browser proof must compare actual cell edges with column/row boundaries before and after long translations, scrolling, and frozen RTL rendering; width/span attributes alone do not prove merge placement.
- A loaded Office view must bind a fresh background version on explicit Refresh only after confirming the Root-expected file identity. Persist/revalidate browser document/window association metadata in trusted session storage so a same-browser service-worker restart does not become a false channel failure. Installed restart proof requires an actual stopped worker and a fresh isolate marker; Playwright may reuse its Worker wrapper without emitting a new event.

- Reader file and worksheet ownership are separate. Within one native spreadsheet file, editor `gid` changes leave Reader selection/content unchanged and perform zero discovery/provider work. The Reader dropdown is authoritative; Refresh retains that selection and latest dropdown responses win. The target is a saved Reader preference shared by native, Drive and local adapters (provider values saved by earlier builds are ignored); Vietnamese is the default only when no valid Reader target has been saved. A different supported file retires old data/work, identifies the current metadata-approved native/Office source, and waits for Translate before value discovery or provider dispatch. Drive lists/folders and unrelated pages close the panel in the affected browser window and retire work; returning never opens or translates automatically. Signed-in supported-editor toolbar clicks open Reader directly with no provider intent only while the remote Sheets Reader flag is on (otherwise the popup shows the ADR 0015 download notice); unsigned users and ordinary sites keep the popup. Unsupported raw CSV/file URLs retain popup/local-file guidance rather than claiming readable-byte support.

Canvas/editor rendering does not provide the DOM text and stable geometry required by the ordinary page pipeline. Translating only Google editor chrome is misleading, while overlaying or writing the file risks selection, formulas, formatting and undo history.

- Exact native Google Sheets/Docs editor routes use extension-owned `/reader.html` and suppress explicit/automatic DOM page translation. Use a window-scoped Chromium side panel with an extension-tab fallback; Chrome owns the user-resizable panel width and Reader fills it. Never add a Google-specific collector, overlay, mutation or layout exception.
- Keep identity, connection, and source state separate. Readlace login is web **Google sign-in** with the single-use handoff code (ADR 0012) or ADR 0010 managed email/password; Google Workspace access never signs anyone into Readlace. **Google Workspace access** uses exactly `spreadsheets.readonly` (ADR 0015 removed `documents.readonly` and restricted `drive.readonly`); `identity` and the Google API host are optional permissions requested synchronously inside the **Connect Google Workspace** click, never required, so `browser.identity` may be absent until Connect and only Connect may require it. The native Sheets Reader is gated by the remote `workspaceSheetsReader` flag (default off; unreadable = off), and Drive Office workbooks show download guidance until `drive.file` + Picker; a same-file worksheet URL change leaves Reader ownership/content unchanged and makes no discovery/provider call.
- Build one portable Chromium Reader with `WXT_GOOGLE_WORKSPACE_WEB_CLIENT_ID`. Chrome, Comet, and Edge use `identity.launchWebAuthFlow()` and the redirect derived by `identity.getRedirectURL("google-workspace")`; there is no browser sniffing or native fallback. Reject the legacy `WXT_GOOGLE_WORKSPACE_CLIENT_ID`. Accept no client secret or Google API key.
- Keep the access token only as a versioned, expiry/account/client/extension/scope-bound `browser.storage.session` record restricted to trusted extension contexts. Restore it after a service-worker restart in the same browser session; clear it on invalid/expired state, Google `401`, Disconnect, logout/account change, or configuration change, while browser/extension lifecycle clears session storage. Never copy it into persistent storage, messages, pages, logs, backend, or provider payloads.
- Clearing a PowerShell process variable does not isolate WXT from a value already present in root `.env`; WXT reloads it during build. Migration must remove `WXT_GOOGLE_WORKSPACE_CLIENT_ID` from `.env`, shell, CI, and build secrets before setting the web client ID. Disabled/enabled-web matrix runs temporarily move `.env` to a collision-checked backup and restore it in `finally`, without reading or rewriting its contents.
- Trust the Reader's bound source tab, not Reader input. Bootstrap, Refresh, recovery, and every operation validate file ownership against that tab. Native Sheets Reader selection is independent of editor gid; Refresh retains it. Same-file editor sheet changes do no Reader work. Invalidate real file/account/source changes and commit only the latest Reader dropdown selection during rapid A → B → C switching. Permit only fixed background GETs to the two Google API origins, bound the streamed response before parsing, and render returned content as plain text.
- Keep the Docs response contract narrow and test the complete supported shape. `documents.get` requests `documentId`, three tab-topology levels and only the body structures Reader consumes; deterministic fixtures must cover child/grandchild tab selection, paragraph text, unsupported equations/inline elements, tables and nested table-cell content.
- Only active native Sheets `GRID` files use the spreadsheet grid. Docs keeps card records; Drive-hosted Office `.xlsx`/`.xlsm` uses the validated read-only saved-snapshot download/parser path with macros disabled (dormant at launch behind `driveOfficeReaderEnabled()`: identification uses the Sheets API and a refused Office file shows download guidance); canvas substitution remains separate experimental evidence rather than a fallback or support claim.
- Discover Sheets columns before first paint. Use allocated `columnCount` only as the boundary, start with 32-column chunks right-to-left and double fully confirmed-empty chunks up to 512 columns with one request pending; reset the next chunk to 32 after splitting. Construct the immutable absolute sequence `[0..lastUsedColumn]`. Combine initial metadata with the first scan and the terminal scan with final grid metadata in one logical operation, retaining authorization before and after. Key fragments, cells, dimensions and merges by absolute indexes so internal blank/hidden positions cannot collapse or reorder.
- Discovery necessarily reads active-sheet values in bounded batches, but only to derive the rightmost populated column. Discard the values immediately; never persist, log, display, translate or send them to a provider. Keep every response under 2 MiB by splitting oversized/timed-out ranges by rows then columns down to one cell. Pause and resume the cursor on rate limit/temporary failure instead of restarting completed chunks or silently polling.
- Load Sheets source/layout in atomic 100-row logical pages and request the next page once near the final 20 loaded rows. Evict distant pages to preserve the 10,000 resident populated-record and 256,000 resident-source-character bounds; fail a single page that cannot fit before provider dispatch.
- Start Sheets provider work only after one explicit **Translate**, then schedule the viewport plus one viewport ahead with one Reader translation message pending. Keep existing cache/validation, adapter concurrency `2`, 4,000 units/record and 128 records/8,000 aggregate units/message. Accepted translations replace source visually; **Translation / Original** is presentation-only and selected-cell details expose both values.
- A Sheets popup **Translate** click must carry a one-shot, source/account-bound target intent into Reader; ordinary panel opening must remain load-only. Keep side-panel opening in the synchronous user gesture and consume the intent once after authorization and source readiness, including the existing-panel and fallback-tab paths.
- After explicit Sheets **Translate**, continue only Reader dropdown worksheet changes when the new grid is ready; editor worksheet clicks never change Reader or dispatch discovery/translation. Persist the Reader target independently of source sessions and adapters, with Vietnamese only when no valid saved Reader target exists. Pause, Clear view, Disconnect, managed logout/session retirement, Reader teardown, and navigation to another file stop continuation. Do not turn a direct Reader open into an automatic provider request.
- Unit browser mocks do not enforce manifest permissions. Any use of `browser.storage.session` requires the `storage` permission in Reader-enabled Chromium builds and an installed-package test. Reader must still show the not-configured state when that capability is absent in disabled builds.
- A scrollable Reader needs a definite viewport-height chain and `min-height: 0` on shrinking flex children. Pin row numbers, column headers and cells to the same explicit grid row. Horizontal column virtualization must not shrink already measured wrapped rows or discard offscreen merge heights. Do not pass per-pixel horizontal position into every memoized row or synchronously measure every row for each horizontal scroll event.
- Use `clamp(1px, API pixelSize or 100px, 420px)` per Sheets column. Preserve newlines, break long lines, allow row growth above the API minimum, and never ellipsize translated grid text. Preserve sticky/frozen/hidden/merged/RTL structure and absolute offsets while mounting visible columns plus two overscan columns only inside loaded pages.
- Docs selection remains checked Reader cards, never the live editor cursor/selection. Docs translation uses the backend-routed stage with no page run, client fallback/native/history or new endpoint.
- Bind every response to Reader owner, source version, source tab, file/sheet/Docs-tab, grid generation, absolute ranges, source hashes, target, request ID and managed-account generation. Deterministic parser/manifest/browser evidence cannot prove configured Google consent, real-file access, Chrome/Comet/Edge Side Panel behavior, or installed-runtime success. Each browser needs observed evidence from the same artifact before a live-support claim.

The governing policy is `docs/google-workspace-reader.md` (Reader launch scope: ADR 0015).

## Used geometry is the only capacity discriminator

Two 2026-08-21 layout regressions shared one root: capacity was not taken from used geometry.

- Tag-gated source glyph width caused false ellipsis on stretched controls: `CONTROL_TAGS` capped a full-width icon+text host at Japanese source width even when remaining owner interval still fit.
- Host-width-blind validation allowed shrink-to-fit action controls to expand: protected geometry ignored host width when no sibling rects existed, so translated text grew the host, action group, and header.

Keep these rules together:

- Used geometry is the only discriminator. Do not use `CONTROL_TAGS` or hostname as a capacity gate.
- Dedicated remaining capacity is the owner content interval after padding, border, icon, gap, measurable pseudo, and visible siblings. It is never the Japanese source glyph width when a larger dedicated owner is proven.
- Shared inline/nav rows without a dedicated owner stay source-capacity-only and must not borrow sibling or row-wide width.
- A captured `single-line` shrink-to-fit host protects its original used border-box. Overflow ellipsizes inside that footprint and must not expand the host, action group, or header.

The governing policy is `docs/decisions/0004-layout-ellipsis.md`.

## Clip boundaries and wrapper styling follow used geometry too

Three 2026-08-21 site failures (office-sheets-man.nativeai.io) shared the same root as before: a rule keyed on something other than used geometry.

- A `truncate` label (clipped, shrink-to-fit `span` in a wider fixed anchor) was capped at source width because the capacity walk treated its own `overflow-x: hidden` as an authored bound. A clip whose used width is content-driven moves with the content; the walk must continue to the real owner above it.
- Content-driven means shrink-to-fit **context**, not a width comparison alone: a block-flow row whose content coincidentally fills its authored width must not read as content-hugging, or capacity escalates past it and internal overflow goes unvalidated.
- The single-line wrapper's fixed glyph-height `block-size` shrank flex controls by 1–2px and inherited `text-align: center` displaced clipped text, so every freeze validation failed and controls fell through to raw growth. The wrapper uses `block-size: auto` and `text-align: start`: identical-by-construction beats recomputed geometry.
- Growth of shrink-to-fit controls into free row space was implemented, demoed, and rejected by the user as layout shift. Controls freeze at their original used border-box; do not reintroduce growth without revising ADR 0004.
- A provider result equal to the source plus trailing punctuation only (brand names in merged pieces returning `NAME:`) is not a translation; apply the exact source instead.

The governing policy is `docs/decisions/0004-layout-ellipsis.md`.

## Batch the pipeline; reflow cost is per interleave, not per node

The 2026-08-21 large-table lag (306-row sales sheet) came from per-record write/read interleaving: every record's raw write invalidated layout and its validation reads forced a full-table reflow, so each record cost 5-15ms and repairs cost ~50-150ms each. Chunked staging fixed it without changing any outcome.

- Apply per response batch in chunks: capture (reads) for the chunk, one write pass, one read validation pass, repairs for the failing subset — no await inside a chunk, so a frame never paints unrepaired raw text.
- Drift the batch itself caused (table columns redistributing) is absorbed by `rebaselineLayoutConstraint` — a read-only re-anchor of every stored rect (all candidates, not just the selected one) — plus re-validation. The host's own footprint must survive the re-anchor: height always, width too for multi-line; otherwise the record goes to repair, or a shrunken translation silently shrinks its paragraph.
- Restore every still-failing source before re-capturing any of them: re-capturing one record under a sibling's raw overflow bakes the squeezed geometry into its baseline (a title frozen at 16px over three lines).
- Sole-text flow is captured too (user decision): single-line flow ellipsizes, multi-line flow clamps to its captured line count; mixed-inline flow stays raw so sentences with markup are never frozen chunk by chunk.
- The 300ms refresh validates under an 8ms budget with a rotating cursor; sample the baseline (marker insertion) lazily at wrapper install, in the captured host frame.

The governing policy is `docs/decisions/0004-layout-ellipsis.md`.

## Capacity ends where descendant chrome begins

Three 2026-08-21 Asahi (asahi.com/ajw) regressions shared one root: measurements ignored geometry that sits between the text and what was measured.

- `dedicatedInlineSize` measured to an ancestor's content end without subtracting the end-side padding/border/margin of elements between the node and that ancestor (a nav anchor's `padding: 0 11px` inside its `<li>`). The phantom capacity made every wrapper overflow its cell by exactly that chrome, every freeze validation failed, and the whole navbar fell back raw and wrapped to a second row. Count border only when its style actually renders — jsdom reports a width for `border-style: none`.
- Forcing nav/repeated-menu items to one line shrank items whose source genuinely renders two lines (submenu cells), failing validation into raw multi-line towers. The captured line count is the footprint; fragmented Range rects are clustered by half the fragment height instead of a fixed 0.5px so noise does not inflate the count.
- Whitespace-only Text siblings adjacent to the wrapped node stop collapsing once an inline-block wrapper separates them and render as real spaces. The wrapper absorbs the contiguous whitespace runs on both sides and releases every child on unwrap (`releaseLayoutWrapper`), preserving node identity and order.

The governing policy is `docs/decisions/0004-layout-ellipsis.md`.

## Do not generalize a user rule beyond its stated reason (2026-10-02)

"Wrap inside the cell" was requested because a background could not cover
overflowing text. Applying it to every cell, including unfilled ones, produced
tall rows unlike the source. State the reason behind a rule and scope the
implementation to it; compare against the source screenshot, not only against
a zero-violation checker. Explicit white fills/borders (common in XLSX) are
visually "none".

## CSS text-decoration does not reach out-of-flow descendants (2026-10-02)

Strikethrough and underline were set on the cell box but the text sits in an
absolutely positioned layer, so neither ever rendered. A style audit of the

## Reader panes are per source tab (2026-10-09)

- Switching browser tabs must not cancel Reader work. `ReaderRoot` keeps exactly one mounted pane per source tab and only hides inactive panes with `visibility: hidden` (not `display: none`), so row measurement, viewport scheduling and in-flight requests are unaffected. Pass `sourceTabId` to `App` as a prop. The global Side Panel must keep the source-neutral `/reader.html` URL; only the extension-tab fallback keeps `?sourceTabId=`.
- The background still requires a _first_ claim for a source tab to come from the window's active tab. After this document has bound that tab, later requests are authorized while another tab is active. Window membership, document identity and source-version checks are unchanged.
- A hidden pane whose file changes is retired and re-identified when the user returns to it. An unrelated page, auth change or tab close still retires panes. This supersedes older wording that a different supported file retires old work on tab switch.
- Worksheet dropdown changes stay inside that browser tab's existing `App`. Reuse the in-place select → discover → load flow so connected controls remain visible with the worksheet skeleton; never mount parallel panes or Reader instances for worksheets in one file.
- Parent callback identity is not source identity. Store the latest source-notification/Office-handoff callbacks separately from the source bootstrap effect; a tab switch must not clear another pane's grid, continuation or pending results. Verify with the built `App` in the real global Side Panel while a provider response is held, asserting unchanged source-request counts after switching and returning across four tabs. A mocked adapter mount assertion cannot prove this.
- Frozen rows are opaque, so an earlier frozen row needs a higher stacking order than later ones (`FROZEN_ROW_Z_BASE + frozenRowCount - index`). With equal `z-index` row 2 paints white over the lower half of a title merge such as A1:L2 and clips its text. Verified in Chromium (merge pixel white at equal z, navy when row 1 is higher); the column header stays above at `z-index: 30`.

## Reader restart and download isolation (2026-10-09)

- A fresh worker epoch is not an explicit Refresh. Keep the mounted native grid, scroll, accepted results and partial progress while re-identifying the same file/worksheet and reloading resident pages. Revalidate source hashes before retaining accepted/unresolved records, and bind continuation to a new run ID/session so old responses cannot apply. Stop during recovery must remain stopped; unchanged unresolved records must not be automatically retried.
- Persist only validated document/window/source/file/account association metadata in trusted session storage. Reclaim an inactive source after a worker restart only when its exact stored claim, current account and browser ownership still match. Never relax first-claim active-tab checks or store spreadsheet text/tokens in claims.
- Drive Office downloads belong to reader-instance/source-tab owners, not a global singleton. Starting another owner's transfer or activating another supported tab must not cancel them. Keep two physical transfers maximum; queued requests begin their timeout only on dispatch. Same-owner replacement, port disconnection, actual source navigation, auth retirement and Google Disconnect still cancel the appropriate work.

- Build deterministic API fixtures into `.output/reader-verification`, never the user's `.output/chrome-mv3`. WXT's `outDir` is the output base, and root `.env` remains active unless explicitly overridden. Verify the final normal artifact contains no test backend origin.

## Quota ledger semantics (2026-10-13)

- Reserve before any provider slot or engine call, in one atomic statement that refuses a stage that would pass the hard cap; never read-then-write in application code. Settle after the stage: charge only records the backend translated, release unresolved ones, and release everything when the stage did not complete (the client may re-dispatch it). A settle failure leaves the reservation charged and never fails the translated response.
- Quota and entitlement refusals are product states, not auth or capacity: `QUOTA_EXHAUSTED` 402 and `ENTITLEMENT_REQUIRED` 403, never 429, classified by JSON code. Throttling above `throttleAt` lowers per-user stage concurrency; it never returns an error.
- Metering stores counts and costs only (ADR 0017): no ledger, cost, error-log or response field carries source or result text. Integration tests assert the column set and dump the rows.
- Any backend test whose app serves `/v1/me` or the stage route against Postgres must apply `0007_quota_ledger.sql`; fake-pool tests stub `QuotaService`.

## Lifecycle email delivery (2026-10-13)

- Send after the trigger committed, never inside it: quota notifiers run after `markThreshold` and must return without awaiting the relay (`QuotaEmailNotifier` sends in the background). Every send claims its `lifecycle_emails` row (user, kind, window end) first, marks it sent after the relay accepted, and releases it after a failed send; a sent row is never re-sent and only a stale unsent claim may be taken over.
- Emails carry counts, dates, the plan and the support address only, never translated content. Logs carry the event, kind and user id only: never the address, subject, body or the relay's error text (it can echo the address).
- The trial reminder is an operator command on a systemd timer, not an in-process interval: one daily run per instance, safe to rerun or overlap because the claim is the dedupe.

## Extension UI localization (2026-10-14)

- The **UI locale** (Vietnamese or English) is presentation only. Internal codes, JSON terminal codes and storage values never change with it, and nothing is classified by message text: map a code to a message key at the UI edge (`lib/i18n/catalog/*`), and keep state as keys or message refs, translated at render, so a switch re-renders correctly.
- English catalogs are the source of truth (`*.en.ts`, `as const`); Vietnamese ones are `Translation<typeof en>`, so a missing key fails `pnpm compile`, and `lib/i18n/messages.test.ts` checks parity, empty strings and matching placeholders. Give every sentence its own key with `{placeholders}` (and `{ one, other }` where English varies by count); never concatenate translated fragments.
- Each surface bundles only its catalogs (common + popup, common + reader + workspace, common + selection). Keys are unique across namespaces because surfaces merge them.
- Only the background reads or writes the `uiLocale` preference. The selection panel asks for it with `UI_LOCALE_GET` on mount and on every open; it adds no listener, timer or host DOM change for it. Extension pages follow the `UI_LOCALE_CHANGED` broadcast and set their own `<html lang>`.
- Tests run in English by default (jsdom `navigator.language` is `en-US`; no provider means English). A mock that answers every runtime message must ignore `UI_LOCALE_GET`. Intl output uses a no-break space in Vietnamese compact numbers (`1,2 Tr`); compare with whitespace-tolerant matchers.
- Brand and plan names stay untranslated (Readlace, Pro, Free); language names are shown in the UI locale, and the language switch shows each language in its own name.

## Handoff binding (2026-10-13)

- A well-formed handoff code from the trusted web origin is not proof that this browser asked to sign in: an attacker can mint a code for their own account and navigate a victim to `/auth/complete#code=…` (login CSRF), and the victim then pays for the attacker's account. The extension accepts a code only with a sign-in request nonce it issued itself (`/signin?ext=` → sealed in the backend transaction cookie → `#code=…&ext=…`), unexpired (10 min), from the tab it opened, consumed once. Anything else answers `unrequested` and changes nothing. Web-only sign-ins issue no code.
- Never clear the current session before a credential exchange has succeeded. A refused/expired/unreachable handoff must leave the signed-in user signed in; the new login generation starts (and old work retires) only when the backend accepted the code.
- `email_verified` is not domain ownership. Auto-link an existing account by email only when Google is authoritative for the address (`gmail.com`/`googlemail.com`, or ID-token `hd` equal to the email domain); otherwise `account_conflict` and operator linking.
